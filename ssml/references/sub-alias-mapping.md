# Mapping technical jargon to human speech

Avoid using acronyms/jargon without explaining how to pronounce it.

Instead, either replace the acronym entirely with a generalized term (e.g. `project documentation` instead of `README.md`) or give explicit direction on how a developer would pronounce the acronym (e.g. `<sub alias="sequel">SQL</sub>`).

These following are ideas, not prescriptive definitions:

```text
*.md: choose the best fit from 
  - "documentation for *
  - "* docs
  - a markdown file

TODO.md: too doo list
```

```text
EC2: E C two (or possibly: just 'instance' or 'server')
S3: S 3 (or possibly: 'object storage' or 'simple storage service')
```

```text
K8s: kyu-ber-net-eez (or kyoob)
SQL: sequel
Postgres: post-gray (or: post-gray sequel)
SQLite: sequel lite
nginx: engine x
uid: user I D
uuid: unique I D
boto3: Amazon SDK for Python
```

```text
regex: reg ex

```
